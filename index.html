01 / How it works

Personal first. Technical underneath.

Anyone can learn about Pulse or submit interest. Actual booking requests are opened only after direct contact and authorization.

1

Submit interest

Tell Pulse who you are, the kind of ride you may need, and how to reach you. This is not yet a booking.

2

Make contact and receive access

Pulse closes the loop directly. Approved riders receive a QR code, secure link, or access code.

3

Request and confirm

Enter trip details, receive a response, and open the rider-facing page when the ride is confirmed.

02 / The local lane

Experienced gig drivers. Real Vermont context.

Pulse is not presenting a public driver marketplace. It is building a small, relationship-based request and communication layer around experienced local gig driving.

🚘

Experienced

Drivers understand passenger service, local roads, event traffic, weather, and timing.

🔐

Authorized

Booking access follows direct contact. A public visitor cannot simply dispatch a ride.

💬

Direct

Requests, confirmations, arrival updates, and changes stay clear and personal.

🗻

Vermont based

The product is shaped around rural distance, small towns, seasonal events, and real local conditions.

03 / Technical

More advanced than it first looks.

  • Private access with unique codes
  • Request and confirmation workflow
  • Foreground location and route status
  • Mobile rider updates
  • Clear privacy boundaries
  • Direct local support

04 / Key features

A closed loop from interest to arrival.

The two sites can be entered independently. Each one points naturally to the other when it is useful.

Ride interest

A public, low-pressure way to make contact without implying a confirmed ride.

Booking access

A code or private link opens the actual booking-request workflow.

Ride status

A confirmed rider can receive ETA, driver-en-route, arrival, and completion updates.

Vermont discovery
